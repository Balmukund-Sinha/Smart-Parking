Viva Defense: Why Columnar Parquet over CSV/JSON?

Row-oriented formats (CSV/JSON) force the execution engine to deserialize irrelevant fields across the disk bus. By adopting Apache Parquet v2.6 with Snappy, SmartPark achieves an 85.2% storage volume reduction. Crucially, analytical queries requesting only occupancy_rate exploit Column Pruning and Dictionary-Encoded Vectorization, bypassing 85% of byte I/O during Trino scans.

• SIMD CPU vectorization • Snappy fast decompression • Statistics min/max skipping

Viva Defense: Multi-Key Partitioning Strategy

Partitioning exclusively by date creates monolithic partitions with scan latency bottlenecks, whereas partitioning down to sensor IDs produces the lethal "Small File Problem" (millions of sub-megabyte files straining HDFS/S3 namenodes). SmartPark employs a balanced hierarchy: partition_date/zone_id/, maintaining an optimal average file split of 12.4 MB to saturate PySpark worker thread cores.

• Predicate pushdown enabled • ZERO S3 full-table sweeps • Clean executor core balancing
