Why Exactly-Once Processing?

At-least-once streaming creates false parking surges and duplicate occupancy billing. SmartPark pairs Kafka offset committing with Delta Lake idempotent write commits and unique event UUIDs, ensuring zero double-counted arrivals even during sudden worker crashes.

Guarantee: Delta ACID WAL + Kafka Offset Sync
alt_route

Disaster Recovery & Rebalancing

Kafka Kraft metadata quorum eliminates external Zookeeper bottlenecks. PySpark relies on resilient DAG lineage graphs: if Worker-02 halts, executors recompute only the lost micro-batch slice directly from preserved in-sync partition replicas in under 420ms.

Convergence: KRaft Quorum + RDD DAG Lineage
memory

Storage Tiering vs Memory Footprint

Querying PostgreSQL or Redis for every sensor event to verify duplicates strains I/O bandwidth. A compact 128KB in-memory Bloom Filter (1M bits, 7 hash passes) eliminates ~1,800 DB queries/minute with a negligible false positive rate of 0.08%.

Savings: ~1,800 DB ops/min saved • 128KB RAM
